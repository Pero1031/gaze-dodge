# Gaze Dodge

視線でプレイヤーを動かし、降ってくる障害物を避けるブラウザゲームです。
入力は **Tobii Pro アイトラッカー**（推奨）、Webカメラ（[WebGazer.js](https://webgazer.cs.brown.edu/)）、マウス（テスト用）から選べます。

## Tobii で遊ぶ

ブラウザは Tobii に直接アクセスできないため、`tobii_bridge.py` が Tobii Pro SDK（`tobii_research`）で視線を取得し、
WebSocket（`ws://localhost:8765`）でゲームへ送ります。ゲーム本体も同じスクリプトが `http://localhost:8000` で配信します。

```
Tobii Pro ──(tobii_research)──> tobii_bridge.py ──(WebSocket)──> ブラウザ (index.html)
```

1. Tobii を接続し、Tobii Pro Eye Tracker Manager で認識・Display setup ができていることを確認
2. `run_tobii.bat` をダブルクリック（または `python -X utf8 tobii_bridge.py`）
3. ブラウザで http://localhost:8000 を開き「Tobii で始める」
4. 全画面になるので「キャリブレーション開始」→ 5 つの赤い点を順に見つめる（点が縮みきるまで）
   - 「スキップ」すると Eye Tracker Manager 等で済ませた現在の校正をそのまま使う
5. 続けて 4 つの緑の点を見つめる（精度の検証）。点ごとに実際の注視点と点のずれを測り、
   **平均のずれが 40 px 以下・目を検出できなかった割合が 20% 以下**なら合格。
   届かなければ自動でやり直し、3 回続けて届かなければ「もう一度」か「このまま進む」を選ぶ
   - 40 px は、この PC の実験環境（幅 51.2 cm・距離 61 cm・1920 px）で約 1°。`Tobii_pro/config.py` の `CALIBRATION_MAX_OFFSET_DEG = 1.0` と同じ目安
   - 全画面でないと画面の位置を概算するため、ずれが大きく出ます
6. プレイヤーを選ぶ（下記）→ ゲーム開始

遅延について:
- ブリッジは Tobii のサンプルが届くたびにすぐ送ります（Pro Fusion は 120 Hz、8.3 ms ごと）
- Tobii 本体と通信の遅れは合わせて約 25〜30 ms。残りはゲーム側の揺れ補正とプレイヤー追従で、上の調整ポイントで変えられます

注意:
- Tobii の座標は Display setup で設定したモニター全体が基準です。ゲームは **そのモニターで全画面** で遊んでください（全画面でない場合はウィンドウ位置から概算します）
- 目を検出できない間はプレイヤーはその場で止まり、0.6 秒以上続くと画面上部に「目を検出できません」と出ます
- **瞬き対策**：瞬きの直前・直後は、まぶたが瞳孔を隠して視線が下にずれたように計測されます。
  目を検出できないサンプルが 3 つ続いたら瞬きとみなし、注視点とプレイヤーを瞬き開始の 0.1 秒前の位置に戻し、
  目が開いてから 0.12 秒間のサンプルは捨てます。
  モックで再現したところ、プレイヤーが下にずれる量と時間は「約 200 px・0.37 秒」から「約 110 px・0.06 秒」に減りました
  （実機は 120 Hz でモックより早く瞬きを検出できるので、さらに短くなる見込み）
- 必要パッケージ: `tobii-research`, `websockets`（このPCには導入済み）

### 実機なしで試す

```
python -X utf8 tobii_bridge.py --mock
```

マウスカーソル位置を視線として送ります（キャリブレーションは常に成功扱い）。
`--mock-ipd 58` のように両目の間隔 [mm] を変えると、別人として候補表示を試せます。
`--mock-blink` で 3 秒ごとの瞬き（直前・直後に視線が下にずれる）を再現、`--mock-pos 0.5,0.5` でカーソルの代わりに決まった位置を見続けます。
ゲームを `?debug` 付きで開くとコンソールの `gazeDebug()` で内部状態を、`?noblink` で瞬き対策を切った状態を確かめられます。

## プレイヤー登録とランキング

ブリッジが動いていれば、どのモードでもプレイヤーごとにスコアを記録し、ゲームオーバー画面にランキングを出します。

- **新規登録**：名前をキーボードで入力。Tobii モードではそのとき 2 秒間「両目の間隔（瞳孔間距離）」を測って一緒に保存します
- **プレイヤー選択**：Tobii モードでは選択画面を開いたときに両目の間隔を測り、登録値が近い人ほど上に並べます（差が 2 mm 以内の先頭の人に「候補」表示）。
  人による差が数 mm しかないため自動で決め打ちはせず、**自分の名前を 1 秒見つめて**選びます（マウスのクリックでも可）
- **「○○さんですか？」**：測った目の間隔との差が 2 mm 以内で、**過去にプレイしたことのある**登録者がいれば、一覧の前に一番近い人について聞きます。
  「はい」でその人として開始、「いいえ」でいつもの一覧に移ります（どちらも 1 秒見つめて選べます）
- **ゲスト**：記録はランキングに残りません
- **登録の削除**：誤操作防止のため、視線ではなくマウスのクリック＋確認ダイアログで削除します（スコア記録も消えます）
- ゲームオーバー画面のボタン（もう一度・プレイヤー交代など）も 1 秒見つめると押せます
- **ランキング**：ゲームオーバー画面に上位 5 人（＋自分）を表示。タイトル画面の「🏆 ランキングを見る」では、
  遊んだことのある登録者全員を自己ベスト順に、プレイ回数つきで一覧できます（ブリッジの起動が必要）

保存先は `data/players.json`（名前・両目の間隔・スコアのみ。画像は扱いません）。`.gitignore` で git の管理対象外にしています。
動作確認などで本番の記録を汚したくないときは、`--data 別のファイル.json` で保存先を切り替えられます。

## Webカメラ / マウスで遊ぶ

上と同じく http://localhost:8000 で開き、「Webカメラで始める」または「マウス」を選びます。
Webカメラモードは画面の 9 点を見つめながら各 5 回クリックして校正します。

## 画像の障害物

`obstacles/` フォルダに画像を置いて `obstacles/obstacles.json` に書き足すと、その画像が障害物として出てきます。
画像ごとに出現確率（全障害物のうちの割合）・大きさ・当たり判定・落ちる速さ・プレイヤーへ寄ってくる速さを決められます。
詳しくは [obstacles/README.md](obstacles/README.md)。
**画像と `obstacles.json` は GitHub に載せません**（`.gitignore` で除外）。

## 調整ポイント（index.html）

- `ONE_EURO_MIN_CUTOFF` / `ONE_EURO_BETA`：Tobii の揺れ補正（One Euro フィルタ）。
  止まっているときは強くなめらかにし、速く動くときは補正を弱めて遅れを減らす。
  プレイヤーが細かく震えるなら `MIN_CUTOFF` を下げ、速い動きで遅れるなら `BETA` を上げる
- `GAZE_SMOOTH`：Webカメラの視線の平滑化（小さいほど滑らかだが遅れる）
- `FOLLOW`：入力ごとのプレイヤーの追従（`rate` が大きいほど遅れが小さい、`maxSpeed` は最大速度）
- `CALIB_POINTS`：Tobii キャリブレーション点（9 点にしたければ追加）
- `CALIB_MAX_ERROR_PX` / `CALIB_MAX_LOSS_PCT` / `CALIB_MAX_ATTEMPTS`：検証の合格基準と自動やり直しの回数。`VALID_POINTS` は検証点
- `BLINK_MIN_SAMPLES` / `BLINK_ROLLBACK_MS` / `BLINK_POST_IGNORE_MS`：瞬き対策（何サンプル欠けたら瞬きとみなすか・どれだけ前に戻すか・開いた直後に捨てる時間）
- `difficulty()`：難易度の上がり方（障害物の速さ・出現頻度）
- `BAR_GAP_START` / `BAR_GAP_MIN` / `BAR_NARROW_FROM` / `BAR_NARROW_PER_SEC`：横バーの隙間。
  20 秒までは 260 px、そこから毎秒 1.5 px ずつ狭まり、約 127 秒で最小の 100 px になる
- `DWELL_SEC`：見つめて押すまでの秒数
- `IPD_MATCH_MM`：「候補」と表示する両目の間隔の差
